# v0.2 Real Product Sprint Implementation Plan

> Steps use checkbox (`- [ ]`) syntax for tracking. PRs land in order; each PR is shippable on its own and ends with the full verification gate green.

**Goal:** Take the v0.1 MVP from "working demo on a LAN" to "credible self-hosted product worth depending on." Close the schema-without-UI gaps (tags, categories, project lifecycle), make the workspace feel finished (real search, list view, mobile sidebar, dark mode), and harden the auth surface enough to survive a reverse proxy. Cut a versioned `v0.2.0` release at the end with a Docker image to match.

**Architecture:** Same shape as v0.1. Next.js App Router with a thin client layer over server APIs, SQLite as the metadata index, direct filesystem storage as source of truth. Add: a CSRF token, a tiny in-process throttle, a token-protected maintenance surface, and a UI tier that finally exposes the schema.

**Tech Stack:** Unchanged — Next.js 15, React 19, TypeScript, Tailwind, `better-sqlite3`, `sharp`, Vitest, Testing Library, Playwright, Docker.

**Verification gate (every PR):**

```bash
npm test && npm run typecheck && npm run lint && npm run build && npm run test:e2e
```

**Branch convention:** `feat/<scope>` for features, `chore/<scope>` for ops/docs, `fix/<scope>` for bugs. Each PR squash-merges to `main`.

## PR 4 — Hardening pass (CSRF, rate limiting, sliding sessions, token-protected maintenance)

Purpose: make it safe enough to leave the LAN. Nothing flashy; everything that should already be true.

### Task 4.1: CSRF token (double-submit cookie)

**Files:**
- Create: `src/lib/server/auth/csrf.ts` — issue + verify.
- Modify: `src/lib/server/auth/guards.ts` — `requireApiSession` checks `x-nas-csrf` header equals the `nas_cloud_csrf` cookie value for `POST`/`PATCH`/`DELETE`.
- Modify: `src/lib/server/auth/http.ts` — set the CSRF cookie alongside the session cookie.
- Modify: `src/lib/client/uploadSessions.ts`, `src/lib/client/fileActions.ts`, `DropZone.tsx`, `AuthForm.tsx`, `LogoutButton.tsx`, `DevicesWorkspace.tsx`, `ArchiveWorkspace.tsx` — read the cookie and send the header.
- Test: `tests/server/csrf.test.ts`, `tests/server/authGuard.csrf.test.ts`, plus a smoke test that any mutation without the header is rejected.

- [ ] CSRF cookie is `SameSite=Lax`, *not* `httpOnly` (must be readable from JS).
- [ ] Auth setup/login/pairing routes are exempted (no session yet).
- [ ] Token rotates on login.

### Task 4.2: Login + pairing rate limiting

**Files:**
- Create: `src/lib/server/auth/throttle.ts` — in-process token bucket keyed by IP + email or pairing-code-hash bucket; persist counters in SQLite for restart resilience.
- Modify: `src/app/api/auth/login/route.ts`, `src/app/api/devices/pair/route.ts`.
- Modify: `src/lib/server/db.ts` — add `auth_throttle (key text primary key, count integer not null, window_started_at text not null)`.

- [ ] Login: 10 attempts / 15 min per email; 60 / 15 min per IP.
- [ ] Pairing: 5 attempts / 10 min per IP, 50 / 24 h per IP.
- [ ] Throttled responses return `429` with `Retry-After`.
- [ ] Tests cover the threshold and reset behavior.

### Task 4.3: Sliding sessions + last-seen

**Files:**
- Modify: `src/lib/server/auth/guards.ts`, `src/lib/server/pageSession.ts` — on each successful auth, `repo.touchSession(sessionId)` and `repo.touchDevice(deviceId)`.
- Modify: `src/lib/server/metadata.ts` — add `touchSession`, `touchDevice`, `extendSession`.
- Modify: `src/lib/server/auth/sessions.ts` — `sessionExpiresAt` becomes a sliding 14-day window from `last_seen_at`.

- [ ] `devices/page.tsx` finally shows real "Last seen X minutes ago" values.
- [ ] Stale sessions older than the sliding window are rejected.
- [ ] Touch is bounded to once per minute per session to avoid write amplification.

### Task 4.4: Token-protected maintenance + TrueNAS cron

**Files:**
- Modify: `src/lib/server/config.ts` — read `NAS_CLOUD_MAINTENANCE_TOKEN` (optional).
- Modify: `src/app/api/maintenance/previews/route.ts`, `src/app/api/maintenance/upload-cleanup/route.ts` — accept either an owner session **or** `Authorization: Bearer <token>` matching the env var.
- Modify: `docker/docker-compose.truenas.yml` — example env var.
- Modify: `docs/deployment/truenas-scale.md` — add a TrueNAS Scheduled Task example that calls both endpoints.
- Test: `tests/server/previewMaintenanceApi.test.ts`, `tests/server/uploadCleanupApi.test.ts` — cover the bearer path and the absent-token-rejected case.

- [ ] When the env var is unset, only session auth works (no silently open endpoint).
- [ ] Bearer comparison uses `crypto.timingSafeEqual`.

### Task 4.5: Defense in depth

**Files:**
- Modify: `src/app/api/files/[id]/download/route.ts`, `src/app/api/files/[id]/preview/route.ts` — add `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'`, `Cross-Origin-Resource-Policy: same-origin`.
- Modify: `src/lib/server/config.ts` — make `appConfig` lazy so a bad env var no longer crashes the server at import time.
- Modify: `src/app/api/files/route.ts` — stream direct uploads to a temp file instead of buffering 2 GiB into memory. Keep the dropzone's chunked path as the default.
- Modify: `next.config.ts` — set `images.unoptimized` only where needed; keep `bodySizeLimit` for server actions if we still use them.
- Test: response-headers tests for download + preview routes.

- [ ] Direct upload streaming uses `request.body` piped to a `createWriteStream` of a temp path produced by the storage service.
- [ ] Header tests assert exact values.
