# v0.3 Preview Pipeline Sprint Implementation Plan

> Steps use checkbox (`- [ ]`) syntax for tracking. PRs land in order; each PR is shippable on its own and ends with the full verification gate green.

**Goal:** Finish the preview story and make the upload story honest. Today only image previews work and the Upload Center only knows about open sessions. By the end of v0.3, video and PDF previews exist, the preview worker runs without a manual cron, the Upload Center reflects the real state of the upload pipeline (open + failed + aborted), and we ship `v0.3.0`. True upload resume is deferred to v0.4 — the browser can't hold a `File` handle across reloads, so a credible resume needs either a desktop helper or an explicit drag-back UX, both of which deserve their own sprint.

**Architecture:** Same shape as v0.2. Add: an opt-in in-process preview scheduler, ffmpeg + pdfjs preview generators (each behind a feature probe), and a richer upload-sessions listing endpoint. No new datastores.

**Tech Stack:** Unchanged base (Next.js 15, React 19, TypeScript, Tailwind, `better-sqlite3`, `sharp`, Vitest, Playwright, Docker). New runtime deps: `ffmpeg` binary on the production image (not an npm dep), and `pdfjs-dist` for PDF page rendering. The Dockerfile already runs Debian-based; adding `ffmpeg` and `poppler-utils` is a single `apt-get` step.

**Verification gate (every PR):**

```bash
npm test && npm run typecheck && npm run lint && npm run build && npm run test:e2e
```

**Branch convention:** `feat/<scope>` for features, `chore/<scope>` for ops/docs, `fix/<scope>` for bugs. Each PR squash-merges to `main`.

## PR 1 — Preview worker loop and Settings visibility

Purpose: stop requiring a manual cron or curl to keep previews current. Surface the pipeline state in the UI so the owner can tell at a glance whether anything is stuck. Make this opt-in via env so dev environments don't fight the test runner.

### Task 1.1: In-process scheduler

**Files:**
- Create: `src/lib/server/previews/scheduler.ts` — start/stop, single-flight, exponential backoff on empty.
- Create: `src/instrumentation.ts` — Next.js `register()` hook that boots the scheduler when `NAS_CLOUD_PREVIEW_SCHEDULER=on`.
- Modify: `src/lib/server/config.ts` — add `previewScheduler: "on" | "off"` defaulting to `off`.
- Test: `tests/server/previewScheduler.test.ts` — fake timers, single-flight, stop semantics, no work when off.

- [ ] Scheduler runs `runPreviewWorker({ limit: 25 })` every 60 s when there is at least one pending row, otherwise sleeps 5 min.
- [ ] Single-flight guard prevents overlapping runs.
- [ ] `stop()` resolves any in-flight run before returning so tests don't leak intervals.
- [ ] `instrumentation.ts` only boots in `runtime: "nodejs"`, never in edge.
- [ ] When `NAS_CLOUD_PREVIEW_SCHEDULER` is unset/`off`, `register()` is a no-op.

### Task 1.2: Preview status API + Settings card

**Files:**
- Create: `src/app/api/maintenance/previews/status/route.ts` — GET-only, owner-session required (no token), returns `{ pending, failed, ready, skipped, lastRunAt }`.
- Modify: `src/lib/server/metadata.ts` — add `countFilePreviewsByStatus(): Record<status, number>` and `lastSuccessfulPreviewAt(): string | null`.
- Create: `src/components/workspace/PreviewStatusCard.tsx` — owner-only Settings card with the four counters, `lastRunAt`, and a "Reprocess failed" button that POSTs `/api/maintenance/previews` with `{ retryFailed: true, limit: 100 }`.
- Modify: `src/app/api/maintenance/previews/route.ts` — accept an optional `retryFailed: boolean` to also reset `failed → pending` before the run.
- Modify: `src/app/settings/page.tsx` — render the card.
- Test: `tests/components/PreviewStatusCard.test.tsx`, `tests/server/previewStatusApi.test.ts`.

- [ ] Status card shows real counts after a fresh upload.
- [ ] "Reprocess failed" button is disabled when `failed === 0`.
- [ ] Status route is a `GET`, so CSRF rules don't block periodic polling from the card (5 s interval while the tab is visible, paused otherwise).

### Task 1.3: Roadmap and README updates

**Files:** `README.md`, `docs/deployment/truenas-scale.md`.

- [ ] README "Known limitations" loses the "Only image previews" bullet for now (we ship a clearer one in PR 2/3) and gains "Preview worker is opt-in via `NAS_CLOUD_PREVIEW_SCHEDULER=on`."
- [ ] Deployment guide adds a one-line note that the env var enables in-process scheduling and the cron approach from v0.2 still works.

## PR 2 — Video poster frames

Purpose: turn the second-most-common upload family (video) into something the workspace grid can show. ffmpeg is the only realistic path; do it carefully so a missing binary degrades gracefully.

### Task 2.1: ffmpeg detection

**Files:**
- Create: `src/lib/server/previews/ffmpeg.ts` — `probeFfmpeg(): Promise<{ available: boolean; version?: string }>` that runs `ffmpeg -version` once and caches the result.
- Modify: `Dockerfile` — install `ffmpeg` in the runtime layer.
- Test: `tests/server/ffmpegProbe.test.ts` — mocked `child_process.spawn`.

- [ ] Probe is memoized for the lifetime of the process.
- [ ] Probe never throws; returns `{ available: false }` on any spawn error.
- [ ] Dockerfile size delta documented in the PR description.

### Task 2.2: Video frame extraction

**Files:**
- Modify: `src/lib/server/previews/worker.ts` — add `generateVideoPoster()` that runs ffmpeg to extract a frame at `min(2s, duration*0.1)`, then pipes it through `sharp` to a 384 px webp.
- Modify: `src/lib/server/previews/worker.ts` — branch on `job.file.family`: `image → existing`, `video → generateVideoPoster`, anything else stays `skipped`.
- Modify: `src/lib/shared/types.ts` — add `unsupported` to `FilePreviewStatus` for the missing-ffmpeg case.
- Test: `tests/server/previewWorker.video.test.ts` — fixture video at `tests/fixtures/sample-2s.mp4`, asserts a webp is written and `width/height/durationSeconds` are populated.

- [ ] When ffmpeg is unavailable, video previews record `status: "unsupported"` instead of `skipped`, and the failure is non-fatal for the worker.
- [ ] Generated poster is square-fit ≤ 384 px, webp quality 82 (matches images).
- [ ] Worker never spawns more than one ffmpeg child at a time per scheduler tick.

### Task 2.3: UI surfacing

**Files:**
- Modify: `src/components/workspace/FileGrid.tsx`, `FileList.tsx` — when a file is `family === "video"` and has a ready preview, show the poster and overlay a small play icon.
- Modify: `src/components/workspace/PreviewStatusCard.tsx` — show an "ffmpeg unavailable" badge when the probe is false.
- Test: component tests for video tile rendering.

- [ ] Video posters render in both grid and list mode.
- [ ] Empty state for "no previews yet" is unchanged.

## PR 3 — PDF first-page previews

### Task 3.1: pdfjs renderer

**Files:**
- Add dep: `pdfjs-dist` (pin to a current major).
- Create: `src/lib/server/previews/pdf.ts` — `renderPdfFirstPage(absolutePath, outAbsolutePath)` returning `{ width, height }`.
- Test: `tests/server/pdfPreview.test.ts` with `tests/fixtures/sample-1page.pdf`.

- [ ] Renders page 1 at a max edge of 1024 px before sharp downsamples to 384 px.
- [ ] Throws clearly when the PDF is encrypted; worker catches and records `status: "failed"`.

### Task 3.2: Worker integration

**Files:**
- Modify: `src/lib/server/previews/worker.ts` — `family === "document"` and extension `pdf` → `renderPdfFirstPage` → sharp.
- Modify: `src/lib/server/previews/worker.ts` — non-PDF documents stay `skipped` with a clearer message ("preview only supported for PDF documents in v0.3").
- Test: extend `previewWorker` tests.

- [ ] Single-page PDF, multi-page PDF, and an encrypted PDF are all covered.
- [ ] Worker timing budget per job stays under 5 s for typical 1–10 page PDFs.

### Task 3.3: README + roadmap

**Files:** `README.md`.

- [ ] "Known limitations" update: "Image, video, and single-page PDF previews are generated. Other document and CAD families are queued and skipped."
- [ ] Roadmap reorder: CAD preview strategy moves up.

## PR 4 — Upload Center reliability

Purpose: make the Upload Center honest. Today it only shows open sessions, which means a partial upload that errored during the chunk loop disappears from the UI even though the temp file lingers. Surface failed and aborted history, add a per-device filter, and clean up orphaned chunks. Resume itself is deferred to v0.4 alongside a desktop helper or explicit drag-back UX.

### Task 4.1: Richer upload-sessions listing

**Files:**
- Modify: `src/app/api/upload-sessions/open/route.ts` → rename to `src/app/api/upload-sessions/route.ts`. Accept `?status=open|failed|aborted|all` and `?deviceId=...`. Default `status=open` for back-compat.
- Modify: `src/lib/server/metadata.ts` — extend `listUploadSessions` to take a `status` filter and a `deviceId` filter. Cap at 100 rows; latest first.
- Modify: `src/lib/client/uploadSessions.ts` — add `listUploadSessions({ status, deviceId })`.
- Test: `tests/server/uploadSessionsApi.test.ts`.

- [ ] Existing `listOpenUploadSessions()` keeps working (thin wrapper that calls the new helper with `status: "open"`).
- [ ] Per-device filter falls through to `null` for sessions created before v0.2's `device_id` column landed.

### Task 4.2: Upload Center tabs

**Files:**
- Modify: `src/components/workspace/UploadCenter.tsx` — segmented control: Active / Failed / Aborted. Default to Active. Per-device filter dropdown.
- Modify: `src/components/workspace/UploadCenter.tsx` — show last error string for failed/aborted, with a copy-to-clipboard affordance.
- Test: `tests/components/UploadCenter.test.tsx` — switching tabs hits the API with the right query params.

- [ ] Switching tabs preserves selection across reloads via `localStorage`.
- [ ] Empty state per tab matches the language the user used to switch in.

### Task 4.3: Server cleanup of orphaned chunks

**Files:**
- Modify: `src/lib/server/uploadCleanup.ts` — also delete temp `.uploads/*.part` files for `failed` sessions older than 24 h, in addition to the existing `open`-stale logic.
- Test: extend `tests/server/uploadCleanup.test.ts`.

- [ ] No new env knobs.

## Out of scope for this sprint

These keep their queue position and ship later:

- Upload resume after a stale or failed session. Needs either a desktop helper that retains the file handle or an explicit drag-back UX; queued for v0.4.
- CAD preview strategy (STL/STEP). Needs a renderer choice spike.
- Bulk download / zip stream.
- File rename in UI; file versioning beyond `name-2.ext` collisions.
- Move-files-on-project-delete (back to `Inbox/`).
- Share / temp-link surface.
- Watch-folder ingest.
- Tauri / Swift / Windows desktop helpers.
- SQLite FTS5 migration.
- Activity log / notifications.
